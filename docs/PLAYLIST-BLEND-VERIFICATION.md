# Playlist blends — 0.2.6

A playlist can now supply both taste references and a small familiar portion of a discovery queue. “Songs similar to my [quoted playlist] playlist, but include a few songs from the playlist too” reserves up to three playlist originals, with fewer for small total counts. An explicit numeric or word count overrides that default. The portion count is parsed separately from the total/dropdown count, and a mix must leave at least one discovery slot. Named/linked original playlists can differ from the reference playlist; explicit liked/playlist source restrictions still constrain both portions.

One AI request selects both portions using compact candidate IDs, playlistCount and eligible playlistIds. The shared ChatGPT/Claude instructions allow seed songs only through those playlist IDs and ask for matching mood/genre in both portions. The client independently caps originals and discoveries: extra originals cannot consume discovery slots, extra discoveries cannot silently replace missing originals, and suggestions cannot claim playlist membership. Reference songs and remastered editions remain excluded from discoveries. Already queued/current/previous songs retain their exclusions unless repeats are explicitly requested; replacement can reuse pending tracks being replaced.

At most 200 candidates, 12 taste seeds, 25 reserves and 50 queued songs remain supported. Up to six distinct playlists are read, each bounded to 200 tracks. Originals receive a spread candidate sample within the 200-candidate budget. Ambiguous names are chosen once per request even when used in multiple roles. Native availability checks apply to both portions, playlist membership is re-read before commit, and explicit source restrictions are also rechecked. Familiar tracks are spread through discoveries. A partial blend reports its counts and missing original portion; no-discovery responses abort instead of replaying a playlist. Ordinary similarity, direct playlist selection and follow-up discovery retain their existing behavior.

Automated verification covers count parsing and negation, explicit and implicit originals, links and multiple named playlists, independently enforced portions, full/partial mixes, no-discovery rejection, duplicate/reference-edition exclusion, one inference, source violations, membership changes and queue exclusions. Helper tests verify compact mixed-selection fields, invalid portions/IDs and legacy-message compatibility. Provider tests use isolated API stubs.

All 138 automated checks passed: 70 extension tests, 47 helper/installer tests and 21 browser UI checks across four viewports. TypeScript checking and bundling succeeded.

The initial live test returned the correct three originals but only four matched discoveries, producing an explained 7-of-25 shortfall. See `blend-inference-initial-proof.json`. This exposed insufficient attention to the numeric portions in the shared generic instructions. Both providers now append explicit calculated primary/reserve counts for a blend: for a 25-song request with three originals and 13 reserves, five playlist proposals and 33 discovery proposals. A helper regression verifies that arithmetic and that ordinary discovery instructions remain unchanged. There is no automatic inference retry.


A recommendation audit found duplicate soundtrack editions with reordered performer credits. Song identity now matches a normalized title through any shared credited performer, preserving differently titled live/remix recordings and same-title covers by different artists. This applies to seed/queue exclusions, candidate uniqueness and final acceptance; reserves can replace rejected alternate-credit duplicates. Two additional regressions cover reordered/expanded credits and a complete blend that excludes those editions.


The final live test on the existing ChatGPT connection and desktop Spotify Premium 1.3.4.258 selected 25 of 25 playable tracks: exactly three originals from the retrieved 27-song playlist and 22 discoveries, across 13 artists. No duplicate recordings remained under the shared-credit song identity check. Eleven selected tracks were by artists outside the full reference playlist. It used 12 seeds, 80 candidates and one inference. Total selection time was 9,445 ms, including 6,427 ms in inference. The completed model answer had 11 proposals beyond the 38-choice budget; the shared parser capped these safely. It still proposed too many eligible originals, but the client enforced the three-original limit independently and filled the 22 discovery slots. See `blend-inference-live-proof.json`.

The direct-source control selected five playlist songs, all within the source, with zero inference calls. Both checks used a read-only verification writer: no queue writes occurred, and current track identity/manual queue entries were unchanged. These are individual observations rather than latency or genre-perfectness guarantees.

See `blend-upgrade-proof.json`, `blend-private-preservation.json` and `blend-installed-files-proof.json`. Private playlist names, song audit and credentials are excluded from the distribution.
